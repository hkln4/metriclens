prefit

Decision-driven EDA for tabular supervised learning. Run it before you fit: it turns what it measures into a short list of decisions, shows the evidence behind each one, tests the ones that depend on your model, and exports only what is safe, confirmed or verified.

pip install "prefit[verify]"
Open the example report GitHub PyPI

What it does

Measures, then decides

Profiles your development data and turns each measurement into a decision with its evidence, 95% interval, rule version and threshold. Near-threshold results are marked uncertain.

Tests instead of assuming

Data- and model-dependent changes (log target, power transform, target encoding, class weights) are tested with bounded experiments on identical folds, with a practical effect threshold.

Asks what only you know

Which error is costlier, whether a column exists at prediction time, whether time order matters: these become questions, and nothing changes until you answer.

Exports only what holds

A scikit-learn model recipe with applied, confirmed or verified steps, plus an explicit list of what was left out and why.

Quickstart

import prefit as pf
from sklearn.ensemble import HistGradientBoostingRegressor

report = pf.analyze(df, "quality", estimator=HistGradientBoostingRegressor(), holdout=0.2)
report = report.answer(task="regression", metric="mae").verify()
fitted = report.export().fit()
review = report.review(fitted)

The holdout is set aside before anything is computed and read once, by review. In a notebook, report shows what is done, what needs you and what was tested, with the next lines to run; report.show() adds the figures behind the decisions that need you.

Four kinds of decision

classwhat it isenters the model recipe when
proceduralhow to evaluate: fit preprocessing inside folds, stratify, keep split columns and the holdout outalways
conditionalmay help or hurt depending on data and modelan experiment with your estimator verifies it
contextualcannot be decided from data: the cost of errors, availability at prediction timeyou answer the question
reviewneeds a human look: duplicates, informative missingness, infinite values, raw dates and textnever; it is a to-do

Honest by construction

Leakage is only ever a hint for manual review. Proxy-model results are a sensitivity analysis, not a verdict on your model. Experiment results are development evidence; the generalization claim comes from data the analysis never read, which prefit checks by fingerprint. Reports are immutable, and every change is a new revision with a history entry.
